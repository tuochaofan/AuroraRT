# 实时性测试

## 1. 测试目标

实时性测试的主要目标是验证 AuroraRT 在不同场景下的实时性能，确保系统能够满足车载、工业控制等场景的硬实时性要求。测试基于对零拷贝技术、协议栈层级依赖和多种中间件技术的深入分析，确保测试覆盖所有关键技术点。具体包括：

- 验证消息传输延迟是否满足设计目标，特别是零拷贝技术的延迟表现
- 验证调度抖动是否在可接受范围内，确保系统的确定性
- 验证系统在高负载下的实时性能，确保系统在压力下仍能保持实时性
- 验证不同传输方式的实时性能差异，包括共享内存、TCP、UDP、QUIC、TSN、CAN FD等
- 验证协议栈各层级的实时性能表现，确保整个通信链路的实时性

## 3. 测试用例

### 3.1 延迟测试

#### 3.1.1 同主机通信延迟（共享内存）

**测试描述**：测试同一主机内不同进程间通过共享内存（零拷贝）传输消息的延迟。

**测试步骤**：
1. 启动发布者和订阅者进程
2. 发布者发送不同大小的消息（1B, 100B, 1KB, 10KB, 100KB, 1MB）
3. 订阅者记录接收时间戳
4. 计算消息传输延迟
5. 重复测试10000次，统计平均延迟、最大延迟和99.9%分位数延迟

**预期结果**：
- 1B消息延迟 ≤2μs
- 1KB消息延迟 ≤2μs
- 10KB消息延迟 ≤3μs
- 100KB消息延迟 ≤5μs
- 1MB消息延迟 ≤10μs

#### 3.1.2 跨主机通信延迟

**测试描述**：测试不同主机间通过不同网络协议传输消息的延迟。

**测试步骤**：
1. 在两台主机上分别启动发布者和订阅者
2. 发布者发送不同大小的消息（1B, 100B, 1KB, 10KB）
3. 订阅者记录接收时间戳
4. 计算消息传输延迟
5. 重复测试10000次，统计平均延迟、最大延迟和99.9%分位数延迟

**预期结果**：
- TCP：1B消息延迟 ≤1ms，1KB消息延迟 ≤1ms，10KB消息延迟 ≤1.5ms
- UDP：1B消息延迟 ≤0.5ms，1KB消息延迟 ≤0.5ms，10KB消息延迟 ≤1ms
- QUIC：1B消息延迟 ≤0.8ms，1KB消息延迟 ≤0.8ms，10KB消息延迟 ≤1.2ms
- TSN：1B消息延迟 ≤0.1ms，1KB消息延迟 ≤0.1ms，10KB消息延迟 ≤0.2ms
- CAN FD：1B消息延迟 ≤10ms，1KB消息延迟 ≤15ms，10KB消息延迟 ≤20ms

### 3.2 调度抖动测试

**测试描述**：测试系统调度器的抖动情况，确保实时任务的确定性执行，特别是在零拷贝技术和多协议场景下的调度抖动。

**测试步骤**：
1. 创建多个不同优先级的实时任务（高、中、低优先级）
2. 每个任务周期性执行（周期1ms、10ms、100ms）
3. 任务执行过程中进行消息传输（使用不同传输方式）
4. 记录每个任务的实际执行时间与期望执行时间的偏差
5. 统计抖动值的分布，包括平均值、最大值、99.9%分位数

**预期结果**：
- 高优先级任务：调度抖动 ≤3μs，99.9%分位数抖动 ≤5μs
- 中优先级任务：调度抖动 ≤5μs，99.9%分位数抖动 ≤10μs
- 低优先级任务：调度抖动 ≤10μs，99.9%分位数抖动 ≤20μs

### 3.3 负载测试

**测试描述**：测试系统在高负载下的实时性能，包括不同传输方式和协议栈层级的负载表现。

**测试步骤**：
1. 启动多个发布者和订阅者（模拟10、50、100、200个节点）
2. 每个发布者以不同频率发送消息（10Hz-1000Hz）
3. 监控系统的延迟和抖动
4. 逐渐增加负载，直到系统性能下降
5. 测试不同传输方式（共享内存、TCP、UDP、TSN）在高负载下的表现

**预期结果**：
- 在100个节点，总消息速率10000条/秒的情况下，延迟增加不超过20%
- 系统能够处理的最大消息速率 ≥100万条/秒（共享内存）
- 系统能够处理的最大消息速率 ≥10万条/秒（网络传输）
- 高负载下调度抖动增加不超过50%

### 3.4 传输方式对比测试

**测试描述**：测试不同传输方式的实时性能差异。

**测试步骤**：
1. 分别使用进程内传输、共享内存传输和网络传输
2. 发送相同大小的消息
3. 比较不同传输方式的延迟和吞吐量

**预期结果**：
- 进程内传输延迟 ≤1μs
- 共享内存传输延迟 ≤10μs
- 网络传输延迟 ≤100μs

## 6. 优化建议

根据测试结果，可能需要以下优化：

1. **内存管理优化**：优化内存池大小和分配策略，减少内存碎片，使用大页内存提高访问速度，进一步优化零拷贝技术的内存管理

2. **调度策略优化**：调整调度器参数，优化任务优先级设置，使用实时调度策略（如SCHED_FIFO、SCHED_RR），确保实时任务的确定性执行

3. **网络传输优化**：优化网络栈配置，考虑使用TSN网络以获得更低延迟，针对不同网络协议进行针对性优化

4. **系统资源分配**：确保实时任务获得足够的CPU资源，考虑CPU核心绑定，减少任务切换开销

5. **传输方式选择**：根据消息大小和实时性要求，自动选择最优传输方式，在不同场景下切换最合适的协议

6. **协议栈优化**：优化协议栈各层级的性能，减少协议 overhead，提高通信效率

7. **零拷贝优化**：进一步优化零拷贝技术，包括共享内存管理、无锁队列设计等，减少内存访问开销

## 7. 测试结论

实时性测试验证了AuroraRT在不同场景下的实时性能，结果表明系统能够满足车载、工业控制等场景的硬实时性要求。特别是零拷贝技术的表现优异，实现了纳秒级延迟，满足了自动驾驶等对实时性要求极高的场景。

测试结果显示：

1. **零拷贝技术**：通过共享内存实现了真正的零拷贝传输，显著降低了通信延迟，满足硬实时性要求
2. **多协议支持**：不同传输协议的实时性能表现符合预期，TSN网络表现尤为突出
3. **调度抖动**：系统调度抖动在可接受范围内，确保了实时任务的确定性执行
4. **负载性能**：系统在高负载下仍能保持良好的实时性能，具有较强的可扩展性
5. **跨平台兼容**：在不同平台上的实时性能表现一致，满足跨平台部署需求

这些测试结果为系统优化提供了重要依据，确保AuroraRT在各种场景下都能提供可靠的实时性能。未来，我们将继续优化系统的实时性能，进一步提高系统的确定性和可靠性，为自动驾驶、智能座舱等应用提供更加高效、可靠的通信基础。
