# AuroraRT 协议栈层级依赖与详细说明（从底层到上层）

---

```
┌─────────────────────────────────────────────────────────────┐

│ 【依赖】第5层：消息/序列化协议层的格式能力                │
├─────────────────────────────────────────────────────────────┤

│ 核心协议：CDR、Protobuf、FlatBuffers、YAS                  │

├─────────────────────────────────────────────────────────────┤

│ 核心协议：RTPS、ZMTP、MQTT、AMQP、SOME/IP、自定义SHM协议    │
│ 【依赖】第3层：服务发现协议层的节点/服务定位能力            │
├─────────────────────────────────────────────────────────────┤
│ 第3层：服务发现协议层（节点/服务动态关联）                  │

│ 【依赖】第2层：安全协议层的身份/加密能力                    │
├─────────────────────────────────────────────────────────────┤
│ 第2层：安全协议层（传输/数据安全保障）                      │
│ 核心协议：TLS 1.3、DDS Security、SROS2、AES-256-GCM        │
│ 【依赖】第1层：网络/硬件协议层的物理传输能力                │

│ 第1层：网络/硬件协议层（物理传输基础）                  │

└─────────────────────────────────────────────────────────────┘
```

## 第1层：网络/硬件协议层（最底层依赖）
### 层级定位
协议栈的最底层，直接对接操作系统内核与硬件驱动，提供物理传输的基础能力，是所有上层协议的根依赖，无更低层级的协议支撑。

### 核心协议详细说明
| 协议名称 | 依赖基础 | 核心作用 | 技术细节 | 适用场景 | 上层依赖该协议的协议 |
|----------|----------|----------|----------|----------|----------------------|
| **UDP（User Datagram Protocol）** | 操作系统网络栈、网卡驱动 | 无连接、低延迟数据传输，上层协议的基础网络载体 | 1. 无握手/挥手流程，报文头仅8B；2. 支持组播/单播；3. 无重传/排序，依赖上层协议保障可靠性；4. 最大报文长度65507B | 实时性要求高的场景（车载传感器数据、工业控制指令）、组播数据分发 | TLS 1.3、SPDP、RTPS、SOME/IP-SD |
| **TCP（Transmission Control Protocol）** | 操作系统网络栈、网卡驱动 | 面向连接、可靠数据传输，保障关键数据不丢失 | 1. 三次握手/四次挥手建立/关闭连接；2. 滑动窗口流控、拥塞控制；3. 序列号去重、重传机制；4. 报文头20-60B | 可靠性要求高的场景（配置下发、故障日志上传、服务调用响应） | TLS 1.3、AMQP、MQTT、ZMTP |
| **CAN FD（Controller Area Network Flexible Data-Rate）** | CAN控制器硬件、CAN驱动 | 车载总线传输协议，适配车载ECU间通信 | 1. 数据段长度扩展至64B（传统CAN为8B）；2. 比特率最高10Mbps；3. 支持帧优先级，避免总线冲突；4. 基于ID过滤接收 | 车载ECU间通信（动力系统、底盘控制、车身电子） | SOME/IP、DDS Security |
| **TSN（Time-Sensitive Networking）** | 支持TSN的网卡、交换机、实时内核 | 时间敏感网络协议，保障实时数据传输确定性 | 1. IEEE 802.1AS：高精度时间同步（偏差≤1μs）；2. IEEE 802.1Qbv：时隙调度，为不同数据流分配专属时隙；3. IEEE 802.1Qcc：流预留，保障带宽；4. 基于以太网硬件实现 | 车载自动驾驶（传感器-决策-控制链路）、工业硬实时控制 | RTPS、SOME/IP、TLS 1.3 |
| **IPC（Inter-Process Communication）** | 操作系统进程管理、文件系统 | 同主机跨进程通信基础协议 | 1. 支持管道、命名管道、信号量、消息队列等；2. 基于操作系统内核实现，无网络开销；3. 传输延迟≤1μs | 同主机跨进程低延迟通信（如感知模块→决策模块数据传输） | ZMTP、自定义SHM协议、SROS2 |
| **共享内存（Shared Memory）** | 操作系统内存管理、硬件内存 | 同主机跨进程零拷贝传输基础 | 1. 物理内存映射至多个进程地址空间；2. 进程直接读写，无内核转发；3. 传输延迟≤100ns | 同主机跨进程大消息零拷贝传输（如激光雷达点云、摄像头图像） | 自定义SHM协议、DDS Security、SROS2 |

## 第2层：安全协议层（传输/数据安全保障）
### 层级定位
基于第1层的物理传输能力，为所有上层的通信提供身份认证、数据加密、访问控制的安全保障，确保传输过程不被窃听、篡改，满足车规/工业安全要求。

### 核心协议详细说明
| 协议名称 | 依赖第1层的协议 | 核心作用 | 技术细节 | 适用场景 | 上层依赖该协议的协议 |
|----------|------------------|----------|----------|----------|----------------------|
| **TLS 1.3（Transport Layer Security）** | UDP、TCP、TSN | 标准传输加密协议，保障网络传输数据不被窃听 | 1. 基于 AES-256-GCM 加密；2. 基于 X.509 证书身份认证；3. 1-RTT 握手，比 TLS 1.2 快 50%；4. 硬件加密加速，降低开销 | 所有网络/云端传输场景 | SPDP、SEDP、RTPS、AMQP、MQTT |
| **DDS Security** | UDP、TCP、CAN FD、共享内存 | DDS 安全框架，满足车规安全等级 | 1. 端到端 AES-256 加密；2. X.509 证书身份认证；3. 细粒度访问控制；4. 兼容 OMG DDS 安全标准 | 车载/工业安全场景 | SPDP、SEDP、RTPS、DDS API |
| **SROS2（Secure ROS2）** | IPC、共享内存、TCP | ROS2 安全访问控制框架 | 1. RBAC 角色访问控制；2. 节点-主题/服务权限映射；3. 安全日志审计；4. 兼容 ROS2 安全标准 | ROS2 兼容场景 | 自定义SHM协议、ROS2 API |
| **AES-256-GCM** | 所有第1层协议 | 对称加密算法，保障数据加密 | 1. 认证加密，同时保障机密性与完整性；2. 硬件加速，加密速度≥10Gbps；3. 无 padding 漏洞 | 所有端到端加密场景 | 所有上层传输/应用协议 |

## 第3层：服务发现协议层（节点/服务动态关联）
### 层级定位
基于第2层的安全能力，实现节点、端点、服务的动态注册与发现，让上层传输协议能自动定位通信对端，无需手动配置地址，支持动态集群。

### 核心协议详细说明
| 协议名称 | 依赖第2层的协议 | 核心作用 | 技术细节 | 适用场景 | 上层依赖该协议的协议 |
|----------|------------------|----------|----------|----------|----------------------|
| **SPDP（Simple Participant Discovery Protocol）** | TLS 1.3、DDS Security | DDS 节点发现协议，去中心化节点定位 | 1. 组播公告节点信息；2. 定期心跳检测离线；3. 兼容 OMG DDS 标准；4. 适配小规模集群（<50节点） | DDS 兼容场景、去中心化集群 | RTPS、SEDP |
| **SEDP（Simple Endpoint Discovery Protocol）** | TLS 1.3、DDS Security | DDS 端点/主题发现协议，动态匹配发布订阅 | 1. 节点间交换端点信息；2. 自动匹配发布者/订阅者；3. 兼容 OMG DDS 标准；4. 支持动态主题更新 | DDS 兼容场景、动态主题 | RTPS、DDS API |
| **SOME/IP-SD（SOME/IP Service Discovery）** | TLS 1.3、DDS Security | 车载服务发现协议，动态服务注册 | 1. 服务上线/下线通知；2. 服务版本匹配；3. 兼容 AutoSAR 标准；4. 适配车载 SOA 架构 | 车载 SOA 场景 | SOME/IP、SOME/IP API |
| **中心化注册协议** | TLS 1.3 | 大规模集群服务发现，中心节点统一管理 | 1. 节点向注册中心注册信息；2. 客户端查询服务地址；3. 心跳保活，自动清理离线节点；4. 适配大规模集群（>100节点） | 边缘计算集群、工业控制集群 | 所有上层传输协议 |

---

## 第4层：传输协议层（数据传输核心）
### 层级定位
基于第3层的节点/服务定位能力，实现数据的端到端传输，提供可靠性、流控、分片等传输能力，是整个协议栈的核心传输层。

### 核心协议详细说明
| 协议名称 | 依赖第3层的协议 | 核心作用 | 技术细节 | 适用场景 | 上层依赖该协议的协议 |
|----------|------------------|----------|----------|----------|----------------------|
| **RTPS（Real-Time Publish-Subscribe）** | SPDP、SEDP、中心化注册协议 | DDS 标准传输协议，跨主机去中心化传输 | 1. 无代理直接通信；2. 心跳+ACKNACK 可靠性；3. 大消息分片重组；4. AuroraRT 裁剪冗余特性，适配车载场景 | 车载/工业跨主机通信、DDS 兼容场景 | CDR、Protobuf、DDS API |
| **ZMTP（ZeroMQ Message Transport Protocol）** | 中心化注册协议 | ZMQ 统一传输协议，多传输抽象 | 1. 多传输统一接口；2. 消息分帧；3. 无代理直接通信；4. 兼容 ZMQ 标准 | 同主机跨进程通信、ZMQ 兼容场景 | 所有序列化协议、自定义API |
| **MQTT（Message Queuing Telemetry Transport）** | 中心化注册协议 | 边缘/云端轻量级传输协议，弱网优化 | 1. 轻量级报文头（最小2B）；2. 3级QoS；3. 心跳保活；4. 弱网缓存补发 | 边缘-云端交互、IoT 场景 | Protobuf、MQTT API |
| **AMQP 0-9-1** | 中心化注册协议 | 企业级消息队列传输协议，灵活路由 | 1. Exchange/Queue 路由；2. 消费确认；3. 持久化；4. 兼容 RabbitMQ 标准 | 企业级集成、运维场景 | Protobuf、AMQP API |
| **SOME/IP** | SOME/IP-SD | 车载 SOA 传输协议，AutoSAR 兼容 | 1. 服务调用/事件通知；2. 大消息分片；3. 兼容 AutoSAR 标准；4. 适配 CAN FD 总线 | 车载 SOA 场景、AutoSAR 兼容 | CDR、SOME/IP API |
| **自定义SHM协议** | 中心化注册协议 | 同主机共享内存传输协议，零拷贝 | 1. 元数据/数据分离；2. 原子引用计数；3. 无锁队列；4. 动态消息支持 | 同主机跨进程零拷贝通信 | FlatBuffers、YAS、ROS2 API |

## 第5层：消息/序列化协议层（数据格式标准化）
### 层级定位
基于第4层的传输缓冲区能力，将业务数据序列化为标准二进制格式，实现跨平台、跨语言的数据兼容，同时提供零拷贝、高性能的序列化能力。

### 核心协议详细说明
| 协议名称 | 依赖第4层的协议 | 核心作用 | 技术细节 | 适用场景 | 上层依赖该协议的协议 |
|----------|------------------|----------|----------|----------|----------------------|
| **CDR（Common Data Representation）** | RTPS、SOME/IP | DDS/ROS2 标准序列化，跨平台兼容 | 1. 字节序无关；2. 自动对齐；3. 兼容 OMG 标准；4. 轻量化实现 | DDS/ROS2/SOME/IP 兼容场景 | ROS2 API、DDS API、SOME/IP API |
| **Protobuf（Protocol Buffers）** | 所有第4层协议 | 跨语言序列化，生态完善 | 1. 紧凑二进制格式；2. 跨语言兼容；3. 向后兼容；4. 生态完善 | 跨语言开发、云端交互 | 所有应用API |
| **FlatBuffers** | 自定义SHM协议、RTPS | 零拷贝序列化，大消息优化 | 1. 无需反序列化直接访问；2. 大消息支持；3. 零拷贝传输；4. 跨语言兼容 | 大消息传输、共享内存零拷贝 | 自定义API、ROS2 API |
| **YAS（Yet Another Serializer）** | 自定义SHM协议、RTPS | 轻量级高性能序列化，实时场景优化 | 1. 极致性能，比Protobuf快2-3倍；2. 轻量化无冗余；3. 跨平台兼容；4. 汇编优化核心逻辑 | 实时/嵌入式场景 | 自定义API |

## 第6层：应用协议层（业务交互入口）
### 层级定位
协议栈的最上层，对接上层业务逻辑，提供标准化的业务交互接口，兼容现有生态，让用户无需关心底层协议细节，直接使用熟悉的API开发业务。

### 核心协议详细说明
| 协议名称 | 依赖第5层的协议 | 核心作用 | 技术细节 | 适用场景 |
|----------|------------------|----------|----------|----------|
| **ROS2 API** | CDR、Protobuf、FlatBuffers | ROS2 兼容接口，支持现有节点直接迁移 | 1. 兼容 rclcpp/rclpy API；2. 兼容 ROS2 消息/服务/动作格式；3. 兼容 ROS2 工具链（colcon、RViz2）；4. 支持 Agnocast 动态消息零拷贝 | ROS2 系统迁移、现有业务迁移 |
| **DDS API** | CDR、Protobuf | DDS 标准接口，兼容 DDS 生态 | 1. 兼容 OMG DDS 标准API；2. 兼容 DDS QoS 策略；3. 兼容 DDS 节点互通；4. 满足车规安全要求 | DDS 系统集成、车载安全场景 |
| **MQTT API** | Protobuf | MQTT 兼容接口，边缘-云端交互 | 1. 兼容 MQTT 3.1.1/5.0；2. 兼容主流云平台；3. 弱网缓存；4. 消息压缩 | 边缘-云端上传、IoT 场景 |
| **AMQP API** | Protobuf | AMQP 兼容接口，企业级集成 | 1. 兼容 AMQP 0-9-1；2. 兼容 RabbitMQ；3. 支持路由/持久化；4. 异步传输 | 企业级集成、运维场景 |
| **SOME/IP API** | CDR | AutoSAR 兼容接口，车载 SOA | 1. 兼容 AutoSAR CP/AP；2. 兼容 SOME/IP 服务调用；3. 适配 CAN FD 总线；4. 支持车载 SOA 架构 | 车载 SOA 场景、AutoSAR 集成 |
| **自定义API** | 所有第5层协议 | AuroraRT 原生轻量级接口 | 1. 极简设计，低开销；2. 支持所有通信模式；3. 动态配置；4. 汇编优化核心路径 | 新业务开发、极致性能场景 |

## 完整依赖链示例
以**车载自动驾驶传感器数据传输**场景为例，完整的协议依赖链如下：
```
业务代码 → 自定义API → FlatBuffers 序列化 → 自定义SHM传输协议 → 中心化注册发现 → AES-256-GCM 加密 → 共享内存 物理传输
```
整个链路从最底层的共享内存硬件，到最上层的业务API，每一层都依赖下一层的能力，同时通过裁剪优化，实现了**纳秒级延迟、零拷贝传输**，满足自动驾驶的实时性要求。

---

## 总结
AuroraRT 的协议栈是一个完整的分层依赖体系，从最底层的硬件/OS 能力，到最上层的业务API，每一层都基于开源标准协议，无自研私有协议，同时通过场景化裁剪优化，解决了标准协议在车载/工业/边缘场景的痛点。所有依赖关系都经过开源项目的大规模验证，确保稳定性与可靠性，可直接指导 AuroraRT 中间件的协议栈开发与落地。
