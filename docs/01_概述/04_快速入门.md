# 快速入门
## 1. 系统要求

### 1.1 硬件要求
  - **CPU**：至少4核心，支持实时调度
  - **内存**：至少2GB（推荐4GB以上）
  - **存储**：至少100MB可用空间
  - **网络**：支持以太网或Wi-Fi（用于跨节点通信）

### 1.2 软件要求

| 平台       | 操作系统版本        | 依赖                         |
|------------|---------------------|---------------------------------|
| Ubuntu     | 20.04 LTS 或更高   | cmake 3.16+, gcc 9+, libprotobuf-dev |
| QNX        | QNX SDP 7.0 或更高 | QNX开发工具链，Protobuf for QNX |

### 1.3 网络要求
  - 支持TCP/UDP/QUIC协议
  - 局域网通信带宽：至少100Mbps
  - 推荐使用有线网络以获得最佳实时性

## 2. 安装与配置

### 2.1 从源码编译

#### Ubuntu平台
```bash
# 克隆仓库
git clone <AuroraRT仓库地址>
cd AuroraRT

# 安装依赖
sudo apt update
sudo apt install cmake build-essential libprotobuf-dev protobuf-compiler

# 编译
mkdir build && cd build
cmake .. -DCMAKE_BUILD_TYPE=Release
make -j4

# 安装
sudo make install
```

#### QNX平台
```bash
# 克隆仓库
git clone <AuroraRT仓库地址>
cd AuroraRT

# 设置QNX交叉编译环境
export QNX_HOST=<QNX工具链路径>
export QNX_TARGET=<QNX目标平台路径>

# 编译
mkdir build-qnx && cd build-qnx
cmake .. -DCMAKE_BUILD_TYPE=Release -DCMAKE_TOOLCHAIN_FILE=../cmake/qnx.toolchain.cmake
make -j4

# 部署到QNX目标系统
# 使用qnxdeploy或scp将编译产物复制到QNX系统
```

## 3. 核心概念

### 3.1 节点（Node）
  - 最小的部署单元，对应一个进程
  - 具有唯一的节点ID和名称
  - 负责管理本地的发布订阅关系

### 3.2 话题（Topic）
  - 消息的分类标识
  - 采用分层命名，如`/sensor/camera/front`
  - 支持QoS策略配置

### 3.3 发布者（Publisher）
  - 向特定话题发布消息的组件
  - 支持消息优先级设置
  - 可配置可靠性级别

### 3.4 订阅者（Subscriber）
  - 从特定话题接收消息的组件
  - 支持消息过滤
  - 可配置接收队列大小

### 3.5 服务（Service）
  - 提供请求-响应模式的通信
  - 由服务端和客户端组成
  - 支持同步和异步调用

## 4. 基础使用示例

### 4.1 发布-订阅示例

#### 发布者代码
```cpp
#include <AuroraRT/AuroraRT.h>

int main() {
  // 初始化节点
  AuroraRT::Node node("publisher_node");
  
  // 创建发布者
  auto publisher = node.createPublisher("/sensor/temperature");
  
  // 定义消息
  AuroraRT::Message msg;
  msg.setTopic("/sensor/temperature");
  msg.setPriority(AuroraRT::Priority::HIGH);
  
  // 发布消息
  while (true) {
    // 填充消息数据
    float temperature = 25.5; // 模拟温度数据
    msg.setData(reinterpret_cast<const char*>(&temperature), sizeof(temperature));
    
    // 发布
    publisher->publish(msg);
    
    // 休眠10ms
    std::this_thread::sleep_for(std::chrono::milliseconds(10));
  }
  
  return 0;
}
```

#### 订阅者代码
```cpp
#include <AuroraRT/AuroraRT.h>
#include <iostream>

void temperatureCallback(const AuroraRT::Message& msg) {
  // 解析消息数据
  float temperature = *reinterpret_cast<const float*>(msg.getData());
  std::cout << "Received temperature: " << temperature << "°C" << std::endl;
}

int main() {
  // 初始化节点
  AuroraRT::Node node("subscriber_node");
  
  // 创建订阅者
  auto subscriber = node.createSubscriber(
    "/sensor/temperature", 
    temperatureCallback
  );
  
  // 运行节点
  node.spin();
  
  return 0;
}
```

### 4.2 服务示例

#### 服务端代码
```cpp
#include <AuroraRT/AuroraRT.h>

AuroraRT::Message addServiceCallback(const AuroraRT::Message& request) {
  // 解析请求数据
  int a = *reinterpret_cast<const int*>(request.getData());
  int b = *reinterpret_cast<const int*>(request.getData() + sizeof(int));
  
  // 计算结果
  int result = a + b;
  
  // 构建响应
  AuroraRT::Message response;
  response.setTopic("/service/add/response");
  response.setData(reinterpret_cast<const char*>(&result), sizeof(result));
  
  return response;
}

int main() {
  // 初始化节点
  AuroraRT::Node node("service_node");
  
  // 创建服务
  node.createService("/service/add", addServiceCallback);
  
  // 运行节点
  node.spin();
  
  return 0;
}
```

#### 客户端代码
```cpp
#include <AuroraRT/AuroraRT.h>
#include <iostream>

int main() {
  // 初始化节点
  AuroraRT::Node node("client_node");
  
  // 创建客户端
  auto client = node.createClient("/service/add");
  
  // 构建请求
  AuroraRT::Message request;
  request.setTopic("/service/add/request");
  
  int a = 10, b = 20;
  char data[sizeof(a) + sizeof(b)];
  memcpy(data, &a, sizeof(a));
  memcpy(data + sizeof(a), &b, sizeof(b));
  
  request.setData(data, sizeof(data));
  
  // 发送请求并等待响应
  auto response = client->call(request);
  
  // 解析响应
  int result = *reinterpret_cast<const int*>(response.getData());
  std::cout << "Add result: " << result << std::endl;
  
  return 0;
}
```

## 5. 多协议配置

### 5.1 协议选择策略

AuroraRT支持根据消息类型和网络条件自动选择最优协议：

| 场景               | 推荐协议 | 配置方式                                   |
|--------------------|----------|--------------------------------------------|
| 进程内通信         | inproc   | 默认使用，无需配置                         |
| 本地跨进程通信     | IPC      | 默认使用，无需配置                         |
| 跨节点高可靠性通信 | TCP      | 设置`qos.reliability = RELIABLE`           |
| 跨节点低延迟通信   | UDP      | 设置`qos.reliability = BEST_EFFORT`        |
| 跨节点移动场景     | QUIC     | 设置`qos.transport_protocol = QUIC`        |

### 5.2 协议配置示例

```cpp
// 配置TCP协议（高可靠性）
AuroraRT::QosProfile tcpQos;
tcpQos.setReliability(AuroraRT::Reliability::RELIABLE);
tcpQos.setTransportProtocol(AuroraRT::TransportProtocol::TCP);

// 配置UDP协议（低延迟）
AuroraRT::QosProfile udpQos;
udpQos.setReliability(AuroraRT::Reliability::BEST_EFFORT);
udpQos.setTransportProtocol(AuroraRT::TransportProtocol::UDP);

// 配置QUIC协议（移动场景）
AuroraRT::QosProfile quicQos;
quicQos.setReliability(AuroraRT::Reliability::RELIABLE);
quicQos.setTransportProtocol(AuroraRT::TransportProtocol::QUIC);

// 创建不同协议的发布者
auto tcpPublisher = node.createPublisher("/sensor/camera", tcpQos);
auto udpPublisher = node.createPublisher("/sensor/imu", udpQos);
auto quicPublisher = node.createPublisher("/vehicle/status", quicQos);
```

### 6.3 常见问题排查

| 问题                   | 可能原因                             | 解决方案                                   |
|------------------------|--------------------------------------|--------------------------------------------|
| 节点无法发现           | 网络配置错误或防火墙阻止             | 检查网络连接，关闭防火墙或添加例外         |
| 消息延迟过高           | 系统负载过高或网络拥塞              | 调整线程优先级，使用更合适的协议           |
| 内存占用增加           | 消息队列溢出或内存泄漏              | 调整队列大小，检查消息处理逻辑             |
| QUIC协议连接失败       | QUIC端口未开放或版本不兼容          | 检查端口配置，确保双方使用相同的QUIC版本   |
| 跨平台通信失败         | 平台差异导致的序列化问题             | 使用Protobuf确保跨平台兼容                |

## 7. 进阶使用

### 7.1 QoS配置

```cpp
// 创建自定义QoS配置
AuroraRT::QosProfile customQos;
customQos.setReliability(AuroraRT::Reliability::RELIABLE);
customQos.setPriority(AuroraRT::Priority::HIGH);
customQos.setHistoryDepth(10);
customQos.setDeadline(std::chrono::milliseconds(10));

// 使用自定义QoS创建发布者
auto publisher = node.createPublisher("/sensor/emergency", customQos);
```

### 7.2 消息过滤

```cpp
// 创建带过滤的订阅者
AuroraRT::MessageFilter filter;
filter.addCondition("temperature", AuroraRT::FilterOp::GREATER_THAN, "30");

auto subscriber = node.createSubscriber(
  "/sensor/temperature", 
  temperatureCallback,
  filter
);
```

### 7.3 动态主题


## 8. 部署最佳实践

### 8.1 生产环境配置
  - **内存配置**：根据实际消息流量调整内存池大小
  - **线程配置**：核心线程绑定到专用CPU核心
  - **网络配置**：使用有线网络，配置合适的MTU
  - **日志配置**：生产环境使用INFO级别，禁用DEBUG日志
  - **安全配置**：启用TLS加密（可选），配置访问控制

### 8.2 容器化部署

#### Docker部署示例

```Dockerfile
FROM ubuntu:20.04

# 安装依赖
RUN apt update && apt install -y \
    cmake build-essential libprotobuf-dev protobuf-compiler \
    && rm -rf /var/lib/apt/lists/*

# 复制AuroraRT
COPY . /AuroraRT

# 编译
WORKDIR /AuroraRT/build
RUN cmake .. -DCMAKE_BUILD_TYPE=Release && make -j4

# 配置
COPY config.json /etc/AuroraRT/config.json

# 运行
CMD ["./bin/AuroraRT_node"]
```
